# Coloring mechanics — the core invariants

Full design: [docs/DESIGN.md](../../../docs/DESIGN.md) §1–3. These are the rules implementation must not violate.

## The non-negotiable mechanic

1. On **press**, sample the region **ID map** at the press point → that region becomes the *locked region* for the whole stroke. Pressing on a line / non-paintable pixel (`#000000`) starts **no** stroke.
2. While **held/dragging**, paint lands **only inside the locked region** — even when the pointer crosses lines into other regions. Never re-lock mid-stroke.
3. On **release**, the stroke ends; update per-region coverage; check page completion. Next press may lock any region.

## How painting is constrained (GPU, not CPU)

- Paint strokes render into a **SubViewport** sized to the page image (stamped brush quads, interpolated along the drag so fast drags leave no gaps).
- The brush shader samples the **ID-map texture** and `discard`s fragments where the ID-map color ≠ the locked region's `id_color` (passed as a uniform). Stroke geometry may freely overlap lines; the shader does the clipping.
- Layer order (back → front): paper background → SubViewport paint texture → **mask texture when the page has one** (BL-12) → line-art / display texture (lines drawn on top).
- **Never** implement per-pixel CPU painting with region checks — it will not hold up on mobile.
- ID map must stay lossless: `.import` keeps `compress/mode=0`, `mipmaps/generate=false`, and `detect_3d/compress_to=0` (default `1` silently VRAM-compresses if the texture is ever seen in 3D — corrupts region IDs). Filtering is **not** an import flag in Godot 4: set `TEXTURE_FILTER_NEAREST` on the node/material that samples the ID map. Guard the `.import` file in diffs.

## Hit-testing & region data

- Press → region id: **pixel lookup in the ID map** (exact, handles enclosed holes for free).
- The `_regions.json` polygons are for: debug overlay tinting, centroids (hint markers), areas, and coverage sample grids — not the paint clip itself.
- Region id encodes into RGB as `id = R<<16 | G<<8 | B`; `#000000` reserved for lines/unpaintable.

## Coverage & completion

- Per region, precompute a sparse grid of sample points (from polygons + area). On **stroke end** (not per frame), sample the paint SubViewport at those points to update coverage. No full-image readbacks in the paint loop.
- A region is "done" at coverage ≥ threshold; a page is complete when all regions are done. There is **one** threshold — the palette's `completion_threshold`, **0.90** (authored data in `PaletteDef`, never a constant in code) — and `CoverageTracker.MIN_REGION_THRESHOLD` (0.85) is a floor no authored value may go under (BL-5). BL-20 removed the per-mode thresholds along with the modes.
- Page complete → the page saves, plays a **transient** celebration (BL-11: a random line from `ColoringPage.CELEBRATION_MESSAGES` above the page + a confetti burst, ~4 s, fading itself out, blocking nothing) and **stays put**. The page-flip transition happens when the **player** asks for the next page (BL-4). **Completion is a celebration, never a gate** (BL-10/BL-11, DESIGN.md §2.1–2.2): a complete page stays fully paintable, and the **last page is not special** — it celebrates like any other, its forward arrow is simply disabled, and Back is the only way out of a book. There is no completion screen, and no `book_completed` signal.

## Input rules (mobile + PC, one code path)

- Use `InputEventScreenTouch` / `InputEventScreenDrag` with *Emulate Touch From Mouse* on — never separate mouse and touch branches.
- Two-finger gesture (pinch/pan) **cancels** an accidental single-finger stroke start.
- Pan/zoom lives on the page view; painting coordinates must be transformed page-local before ID-map lookup.

## PageView component (implemented — M2)

`scenes/components/page_view.tscn` / `scripts/components/page_view.gd` (`class_name PageView`) is the built, verified painting component. Read its doc comments for the full API; load-bearing facts:

- Inject pages via `load_page(base, idmap, regions)` or the three exported path properties — never hardcode page paths inside it.
- Signals: `page_loaded(page_size)`, `region_locked(region_id)`, `stroke_ended(region_id)` (the coverage hook — fires exactly once per stroke, **including after a cancel**, since committed paint remains), `stroke_cancelled(region_id)` (fires just before `stroke_ended` on aborts).
- `brush_size` is **diameter** in page pixels (default 56); parent sets `brush_color`/`brush_size`/`brush_hardness`.
- `get_region_id_at(page_pos)` → 0 = line art, -1 = out of bounds. `get_region_data(id)` returns the JSON region dict for coverage-grid precomputation.
- `get_paint_image()` is a full GPU readback and **blocks** — dev harnesses and the app-quit save only. In the running game use `request_paint_image(callback)` (M6, async). Coverage must sparse-sample at stroke end either way.
- Region clipping lives in `scenes/components/brush.gdshader` (`id_epsilon` = half an 8-bit step; ID map sampled with `filter_nearest` hint). The SubViewport is never cleared (`CLEAR_MODE_ONCE`→NEVER); `PaintCanvas` draws only the pending stamp batch each frame.
- `painting_enabled` (BL-10) is the ONE additive gate: false → `begin_stroke()` refuses and emits `paint_blocked(page_position)` instead, and a stroke already down is cancelled. Nothing else in the component reacts to it — pan/zoom and the committed paint are untouched. That flag is the whole component-side surface of the coloring lock.
- Smoke test: `<godot_exe> --path godot res://scenes/dev/paint_smoke.tscn` (windowed — headless can't render the SubViewport; append `-- --stay` for manual play, F1 toggles the region overlay). Keep it green after any change to the painting stack.

## The palette — one crayon strip (BL-20…BL-23)

**There is no Child/Adult mode.** BL-20 deleted the split: no mode-select screen, no settings mode switch, no adult palette, no swatch grid, no brush-size slider, and no `GameState.mode`. One flow, one palette, one threshold. `GameState.mode` and the save's `"mode"` key are vestigial — the save READER tolerates the key (`GameState.VESTIGIAL_SAVE_KEYS`) so pre-BL-20 files load at the same `SAVE_VERSION`, and nothing writes or branches on it. Never re-introduce a mode parameter.

- `palette_child.tscn` / `PaletteChild` is **the** palette (the name is historical and deliberately kept — DESIGN.md §3.4 names it): a strip of chunky crayons, 64 px+ touch targets, ONE forgiving 96 px brush, `completion_threshold` 0.90.
- It emits `color_picked(color)` and `brush_size_picked(size)` and **nothing else reaches the paint path**. Everything below (layout, intensity, crayon sets) is resolved inside the palette; `color_picked` always carries one final `Color`.

### Implemented (M3, reshaped by BL-20…BL-23) — build against these, don't reinvent

- `PaletteDef` (`scripts/resources/palette_def.gd`): `display_name`, `colors` (the DEFAULT crayon box — also what the title screen, the boot splash and the celebration confetti read), `brush_sizes` (**diameters**, feed `PageView.brush_size` directly — shipped `(96)`), `default_brush_size`/`default_brush_hardness`, `completion_threshold` (0.90). Plus the two derived-feature APIs below. It carries **no** mode id and no `shades_per_family`.
- **Intensity ladder (BL-22)** — `PaletteDef.shade_of(base, step)` / `shades_of(base)`. A pure function, never authored: `INTENSITY_STEPS` 7, `INTENSITY_BASE_STEP` 3 (= the crayon's own colour), lightened linearly to `MAX_TINT` 0.72 below it and darkened to `MAX_SHADE` 0.60 above. Because it is computed, every crayon of every set has a ladder and no set can ship without one. Do not add a per-colour shade table.
- **Crayon sets (BL-23)** — `CrayonSetDef` (`scripts/resources/crayon_set_def.gd`): `display_name`, `sort_order`, `colors`, **and nothing else** — a set that could carry a brush size or a threshold would be a difficulty mode again. Sets are **discovered**, like books: `CrayonSetDef.discover()` scans `res://resources/palettes/sets/*.tres`, sorted by `sort_order`. Shipped: Pastel, Neon, Earth, Candy, Spooky. `PaletteDef.get_crayon_set_colors(i)` / `get_crayon_set_name(i)` / `crayon_set_count()` / `wrap_crayon_set(i)` present box 0 (the palette's own `colors`) and the discovered sets through one index.
- `GameState` autoload (`autoload/game_state.gd`): `get_active_palette()` (one cached `PaletteDef`), `get_palette_scene_path()` (one scene). No mode property, method or signal. Extend it for book/page state and persistence (M5) — no second autoload.
- **Palette contract** — `set_palette(def)` (auto-emits `brush_size_picked` then `color_picked` once each, so the brush is never colourless), `color_picked(color)`, `brush_size_picked(size)`, `select_color(i)`, `select_brush_size(i)`, `get_selected_*()`, `get_color_buttons()`, `get_brush_size_controls()` (always empty — one brush), `get_pick_preview()` (BL-15). Wiring a coloring screen = instantiate `GameState.get_palette_scene_path()`, connect those two signals to `PageView.brush_color`/`brush_size`, set `brush_hardness` from the def, call `set_palette`, then `set_layout()` for the orientation.
- **The pick is always "crayon C of box B at rung R"**, resolved in `PaletteChild.get_selected_color()` and nowhere else. `select_color(i)` picks the crayon and **resets the rung** to the crayon's own colour; `select_intensity(step)` picks the rung; `set_crayon_set(i)` / `next_crayon_set()` swaps the box (and resets to its first crayon, own colour, colours face). Swapping the VIEW (`set_view()`, `VIEW_COLORS` / `VIEW_SHADES`) emits nothing — it is not a pick.
- **Two tool tiles on the strip**, both primitive-drawn, both OUTSIDE the crayon `ScrollContainer` so a slide can never land on one: `CrayonBoxButton` (BL-23, cycles boxes, draws the current box + a pip per box) then `IntensityButton` (BL-22, swaps colours ↔ ladder, draws the ladder with the ACTIVE rung ringed). 88 px each; they share the strip's SHORT axis with its margins (188 px in a row, 184 px in a column) and fit with ~2 px to spare — **growing one, or adding a third, overflows the strip silently**. The palette smoke measures every tool tile against the strip's rect in all three layouts.
- Smoke test: `<godot_exe> --path godot res://scenes/dev/palette_smoke.tscn` (windowed; `-- --stay` to inspect, `-- --shot <path>` saves a screenshot). Keep green alongside paint_smoke.

### Layout: bottom row or side dock (BL-21)

- Portrait keeps the crayons in a strip along the **bottom** of the canvas; landscape docks them as a vertical **column** on the side. Same scene, same instance — `PaletteChild.set_layout(LAYOUT_ROW | LAYOUT_COLUMN)` flips the body box's direction, the scroller's axis, the crayons' orientation and the pick bubble's placement. `STRIP_THICKNESS` (212 px) is the strip's short axis either way.
- **The parent decides, from its ASPECT RATIO** — `ColoringPage.is_landscape()` is `size.x > size.y`, never a pixel width (DESIGN.md §3.5: a portrait window's logical canvas never gets narrow). `coloring_page.tscn`'s `Ui/Body` is a plain `BoxContainer` because `HBoxContainer`/`VBoxContainer` refuse `set_vertical()`.
- `CrayonButton` draws in a **canonical** space (tip up, lift rising) and `ORIENT_LEFT` rotates it a quarter turn anticlockwise before anything is drawn. Consequences that come for free and must stay that way: the lift points **into the canvas** in both orientations, `LIFT_HEADROOM` still reserves the bounce overshoot at the canonical top, and the halo still flattens along the axis the scroller clips. Use `box_for(orientation)` / `lift_direction()`; never fork the drawing code.
- `PickPreview` parks **above** the finger for the bottom row and **left** of it for the right-hand column (`PLACE_ABOVE` / `PLACE_LEFT`); the whole geometry is one direction vector (`get_tail_direction()`), so a third placement is one constant. Slide-to-select needs nothing: `PaletteSlideInput` hit-tests real control rects in viewport space.
- Known trade: ten crayons do not fit a docked column on a short landscape canvas, so the strip scrolls. That is correct — a BL-23 set can be any length.

### Implemented (M4) — books, coverage, flip

- `PageDef`/`BookDef` resources (`scripts/resources/`). ### Implemented (M5) — app shell & persistence

- `main.tscn` / `scripts/main.gd` (`class_name Main`) is `run/main_scene` and the **only** node that knows the flow: Title → BookSelect → ColoringPage → (Back) → BookSelect. There is no mode select (BL-20) and no completion screen (BL-11). It frees/instantiates screens behind a 0.25 s fade, and owns the **overlays** (settings gear, settings panel, and WP10's adult gate / account panel / pack shop) — that is how `book_select.tscn` stayed frozen while gaining a settings entry point.
- `GameState` owns all of `user://` (nothing else opens a file there): `user://save_v1.json` (`{version, books{<resource_path>: {slug, current_page_index, pages[]}}}` — pre-BL-20 files also carry a `"mode"` key, which is read past and never written back, statuses `untouched`/`in_progress`/`complete`) and `user://paint/<book_slug>/page_NN.png`. `book_slug` = book directory name sanitised + `_` + 8 hex of a hand-rolled FNV-1a of the full resource_path (hand-rolled so it cannot change with the engine). API: `save_now`/`load_save`/`get_book_progress`/`mark_page_status`/`erase_book_progress`/`erase_all_progress`/`get_paint_path`/`save_page_paint`/`load_page_paint`, signal `save_written`. `set_save_root()` is the **test isolation hook** — all four dev smokes point it at a scratch dir, because a restored paint layer would otherwise break their "starts blank" assertions.
- Save points for the paint layer (one `get_paint_image()` readback each, never more): page complete (before the flip advances), leaving the book, app quit (`NOTIFICATION_WM_CLOSE_REQUEST` / `APPLICATION_PAUSED`, handled in `main.gd` so the open page is flushed before the JSON).
- **Paint restore**: `PageView` is frozen and has no `set_paint_image()`, so `ColoringPage.PaintRestoreQuad` composites the saved PNG into the paint SubViewport for exactly ONE frame using `BLEND_MODE_PREMULT_ALPHA` over the freshly cleared (all-zero) target — that is bit-exact; plain MIX would darken soft dab edges on every save/restore cycle. The tracker is then re-seeded with `CoverageTracker.update_all(image)` using the same CPU image (no second readback). A page whose restored paint already completes it does **not** celebrate or flip (`is_page_pre_completed()`).
- ~~Mode is now changeable mid-book: `ColoringPage` rebuilds the palette component and re-injects the threshold~~ — **deleted by BL-20** with the modes, along with `ColoringPage.palette_rebuilt`. One palette, one threshold, fixed for the visit.
- Shell smoke: `<godot_exe> --path godot res://scenes/dev/shell_smoke.tscn` (windowed; `-- --stay`, `-- --shot-dir <dir>`).

### Implemented (M6) — the mobile pass

- **Renderer is now Mobile** (Vulkan), not Forward+. Chosen because Compatibility/OpenGL exposes **no `RenderingDevice`**, which would kill the async readback below; between the two Vulkan renderers, Mobile is the cheaper pipeline for a 2D game. DESIGN.md §3.5 has the evidence. Anything that touches `RenderingDevice` must still degrade gracefully when it is absent.
- **The paint readback is asynchronous.** `AsyncReadback` (`scripts/components/async_readback.gd`, static helpers over an injected `Viewport`) wraps `RenderingServer.texture_get_rd_texture()` → `RenderingDevice.texture_get_data_async()`. `PageView.request_paint_image(callback)` is the non-blocking twin of `get_paint_image()`; it returns **false without calling back** when the async path is unavailable, which is the caller's cue to fall back to the blocking call. Measured on the M6 dev box under default FIFO v-sync: **529.8 ms blocked synchronously → 0.10 ms** to queue the async one, image delivered on the **main thread** ~2 frames later.
  - `get_paint_image()` is still there and is still correct — dev harnesses and the app-quit save use it deliberately.
  - Two rules come with async: a readback can be a couple of frames stale (fine, coverage is monotonic and the completion flip already tolerated it), and **the engine must never be torn down while a readback is queued** — that is a reproducible hard crash (signal 11 during shutdown, any renderer). `AsyncReadback.drain(tree)` before any `SceneTree.quit()`; `main.gd` does it on close, every dev harness does it in `_finish()`.
- **`main.gd` owns the quit**: `SceneTree.auto_accept_quit` is off, and `NOTIFICATION_WM_CLOSE_REQUEST` runs save → drain → quit. `Main.quit_on_close_request = false` is the harness hook (it hands `auto_accept_quit` back so a `--stay` window still closes).
- **`ColoringPage` coverage** is a *loop* now (`_run_coverage_cycles`): a stroke ending during the two-frame flight lands in `_pending_regions` after the batch was taken, so the cycle repeats until that set is empty. Coalescing and skip-when-done are unchanged — five strokes in one burst still cost one readback.
- **Save points** unchanged in *when*, changed in *how*: page complete / leaving the book / navigating use `persist_current_page_settled()` (async); app quit uses `persist_current_page()` (blocking — there is no next frame to deliver to, and losing a page is worse than a stall on a frame nobody sees). Leaving the book **awaits** the save before emitting `back_requested`, or the parent would free the screen out from under the callback.
- **Page navigation**: `ColoringPage.can_go_to_page()` / `go_to_page()`, driven by prev/next buttons in the toolbar. A jump **saves first, then swaps instantly** — no flip (BL-4 carved out one exception: the forward step off a page the player just finished, which is now where the flip lives). `is_transitioning()` now covers navigation too. ~~Rule: any page already reached … plus exactly one page forward when the current page is complete~~ — **BL-10 deleted that gating and `furthest_reached_index()` with it**; every page is always reachable.
- **Portrait**: ~~`ModeSelect` stacks its cards below aspect 1.0~~ (that screen is gone, BL-20 — but its lesson is now BL-21's: a container that has to flip must be a plain `BoxContainer`, because Godot refuses `set_vertical()` on `HBoxContainer`/`VBoxContainer`); `TitleScreen` sizes its paper and lettering to the screen instead of demanding 820 px; `ColoringPage` drops the toolbar's page title below 620 px; `SafeArea` (`scripts/components/safe_area.gd`) wraps `ScreenHost` + `Overlays` in `main.tscn` for notch margins (zero on a windowed desktop by design — `get_display_safe_area()` reports the *work area* there, not a cutout). Gotcha: `canvas_items`/`expand` stretch means the logical canvas never gets narrower than 1152 — portrait layouts must key off **aspect**, and width-driven ones have to be tested by resizing the screen `Control`, not the window.
- **First real art book**: `resources/books/coyote/` + `assets/books/coyote/`. **ONE page** (corrected by BL-9 — it was briefly imported as two): the visible art is the detail drawing, its 2 regions (coyote + paper) come from the outline mask. The artist's full-resolution ORIGINALS live in `assets/books/coyote/source/` behind a `.gdignore` and still ship with nothing; what ships is the pipeline's resampled `page_01_mask.png` next to the idmap, which BL-12 renders as a layer.
- **Mobile smoke**: `<godot_exe> --path godot res://scenes/dev/mobile_smoke.tscn` (windowed; `-- --stay`, `-- --shot-dir <dir>`). It deliberately does **not** set the v-sync mode for its headline check — the async stall budget is only meaningful under default FIFO.

### Implemented (backlog BL-1..13) — see [docs/BACKLOG.md](../../../docs/BACKLOG.md) for the full notes

- **BL-4 flip**: `scenes/components/page_curl.gdshader` — one full-screen quad, one `progress` uniform (CUBIC/IN_OUT tween), a leaning fold line with a lit crease, the paper folding back over itself and a travelling cast shadow. `progress == 0` is a pixel-exact pass-through, which is what keeps `PageFlip.prepare()`'s hand-off invisible. `PageFlip`'s API is unchanged.
- **BL-4 no auto-flip**: completion saves and plays the transient celebration (BL-11); `ColoringPage.go_to_page()` plays the flip for the forward step off a finished page ONLY, and swaps instantly for every other jump (BL-10 narrowed "finished" to *finished during this visit* — `_completed_this_visit` — so re-opening an already-complete page and stepping forward is browsing, not ceremony).
- **BL-5 thresholds**: `CoverageTracker.COVERED_ALPHA` 128 → 160, new `MIN_REGION_THRESHOLD` floor 0.85, child 0.90 / adult 0.96 — **BL-20 kept the child 0.90 as THE threshold** and deleted the other.
- **BL-6 autosave**: `GameState.AUTOSAVE_INTERVAL_SECONDS` (45 s) `Timer` → `autosave_due` → `ColoringPage.save_page_now()`. **Never reads the paint layer mid-stroke** — a save asked for during a stroke (or an in-flight coverage readback) is deferred to `stroke_ended`. `_paint_dirty` skips clean pages. Manual Save button in the coloring toolbar (the settings gear is hidden while a book is open). `NOTIFICATION_APPLICATION_FOCUS_OUT` in `main.gd` is an extra save point.
- **BL-7 start over**: `ColoringPage.restart_current_page()` (generation bump → `PageView.clear_paint()` → fresh tracker → `GameState.erase_page_progress()`), behind an in-game two-button confirm overlay. Never an OS/JS modal — this ships to the web. `erase_page_progress()` is the only path that downgrades a page status.

- **BL-9 display/mask pages**: `PageDef` gained `display_image_path` (renamed from `base_image_path`) + optional `mask_image_path`; `tools/generate_region_map.gd` gained `--display` (map from the mask, write the artifacts next to the page art, resampling the mask to its size). ~~The runtime is unchanged — the mask is never loaded or rendered~~ — **BL-12 reversed that**, see below. `GameState._entry_for()` now trims a save entry when a book gets SHORTER, so the old two-page coyote save cannot leave statuses or paint PNGs for a page that no longer exists.

- **BL-10 free play**: three rules and a lock — see [docs/DESIGN.md](../../../docs/DESIGN.md) §2.1, which is authoritative.
  1. **Every page is always reachable.** `can_go_to_page()` is now "is that a page of this book, and not the one already open"; `furthest_reached_index()` is gone. Completing a page unlocks nothing because nothing was ever locked.
  2. **A complete page stays fully paintable**, in the sitting and after reopening. Completion is sticky (only *Start over* downgrades it, BL-7), the celebration cannot re-fire (`CoverageTracker.page_completed` is once-per-tracker, and a restore sets `_pre_completed`), and post-completion strokes still mark the page dirty, run a coverage cycle and save.
  3. **The book ends when the player says so.** Completing the LAST page celebrates and stays put. **BL-11 finished the job**: there is no finish-book gesture, signal or screen at all — the forward arrow is simply disabled on the last page, and the player leaves with Back like they always could.
  4. **Coloring lock**: per-page padlock in the coloring toolbar (`PadlockButton`, `scripts/components/padlock_button.gd`, drawn from primitives). Locked = `PageView.painting_enabled = false` (no strokes; the refused press comes back as `paint_blocked` and shakes the padlock) **and** Start over disabled — nothing else changes. One tap on, one tap off, no confirm.
  - **Save format**: a `pages[]` entry is now `{"status": …, "locked": …}` instead of a bare status string, at the SAME `SAVE_VERSION` (1) — `GameState._to_page_entry()` accepts either shape, so a pre-BL-10 file loads with every page unlocked, and `_page_slot()` upgrades a slot when it is next written. The lock is written with `save_now()` the moment it is set and is untouched by `erase_page_progress()`.
