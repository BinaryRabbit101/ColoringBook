# Coloring mechanics — the core invariants

Full design: [docs/DESIGN.md](../../../docs/DESIGN.md) §1–3. These are the rules implementation must not violate.

## The non-negotiable mechanic

1. On **press**, sample the region **ID map** at the press point → that region becomes the *locked region* for the whole stroke. Pressing on a line / non-paintable pixel (`#000000`) starts **no** stroke.
2. While **held/dragging**, paint lands **only inside the locked region** — even when the pointer crosses lines into other regions. Never re-lock mid-stroke.
3. On **release**, the stroke ends; update per-region coverage; check page completion. Next press may lock any region.

## How painting is constrained (GPU, not CPU)

- Paint strokes render into a **SubViewport** sized to the page image (stamped brush quads, interpolated along the drag so fast drags leave no gaps).
- The brush shader samples the **ID-map texture** and `discard`s fragments where the ID-map color ≠ the locked region's `id_color` (passed as a uniform). Stroke geometry may freely overlap lines; the shader does the clipping.
- Layer order (back → front): paper background → SubViewport paint texture → **mask texture when the page has one** (BL-12) → line-art / display texture (lines drawn on top) → **`StickerLayer` (BL-36)**.
- **The effect mask (BL-38)** is a *second* SubViewport beside the paint one, stamped by the **same brush shader** (`effect_target = TARGET_MASK`) so it is region-clipped by the same `discard`; `paint_display.gdshader` on the PaintSprite animates the paint wherever the mask is non-zero. It is **dormant** (2×2, never rendered) until an animated finish is in hand. Never read it for coverage, never composite it over the paint layer, and never give it a clip of its own — the whole design rests on the mask being written by the fragment that decided the wax survived.
- **Never** implement per-pixel CPU painting with region checks — it will not hold up on mobile.
- ID map must stay lossless: `.import` keeps `compress/mode=0`, `mipmaps/generate=false`, and `detect_3d/compress_to=0` (default `1` silently VRAM-compresses if the texture is ever seen in 3D — corrupts region IDs). Filtering is **not** an import flag in Godot 4: set `TEXTURE_FILTER_NEAREST` on the node/material that samples the ID map. Guard the `.import` file in diffs.

## Hit-testing & region data

- Press → region id: **pixel lookup in the ID map** (exact, handles enclosed holes for free).
- The `_regions.json` polygons are for: debug overlay tinting, centroids (hint markers), areas, and coverage sample grids — not the paint clip itself.
- Region id encodes into RGB as `id = R<<16 | G<<8 | B`; `#000000` reserved for lines/unpaintable.

## Coverage & completion

- Per region, precompute a sparse grid of sample points (from polygons + area). On **stroke end** (not per frame), sample the paint SubViewport at those points to update coverage. No full-image readbacks in the paint loop.
- A region is "done" at coverage ≥ threshold; a page is complete when all regions are done. There is **one** threshold — the palette's `completion_threshold`, **0.90** (authored data in `PaletteDef`, never a constant in code) — and `CoverageTracker.MIN_REGION_THRESHOLD` (0.85) is a floor no authored value may go under (BL-5). BL-20 removed the per-mode thresholds along with the modes.
- Page complete → the page saves, plays a **transient** celebration (BL-11: a random line from `ColoringPage.CELEBRATION_MESSAGES` above the page + a confetti burst, ~4 s, fading itself out, blocking nothing) and **stays put**. The page-flip transition happens when the **player** asks for the next page (BL-4). **Completion is a celebration, never a gate** (BL-10/BL-11, DESIGN.md §2.1–2.2): a complete page stays fully paintable, and the **last page is not special** — it celebrates like any other, its forward arrow is simply disabled, and Back is the only way out of a book. There is no completion screen, and no `book_completed` signal.

## Input rules (mobile + PC, one code path)

- Use `InputEventScreenTouch` / `InputEventScreenDrag` with *Emulate Touch From Mouse* on — never separate mouse and touch branches.
- Two-finger gesture (pinch/pan) **cancels** an accidental single-finger stroke start.
- Pan/zoom lives on the page view; painting coordinates must be transformed page-local before ID-map lookup.

## PageView component (implemented — M2)

`scenes/components/page_view.tscn` / `scripts/components/page_view.gd` (`class_name PageView`) is the built, verified painting component. Read its doc comments for the full API; load-bearing facts:

- Inject pages via `load_page(base, idmap, regions)` or the three exported path properties — never hardcode page paths inside it.
- Signals: `page_loaded(page_size)`, `region_locked(region_id)`, `stroke_ended(region_id)` (the coverage hook — fires exactly once per stroke, **including after a cancel**, since committed paint remains), `stroke_cancelled(region_id)` (fires just before `stroke_ended` on aborts).
- `brush_size` is **diameter** in page pixels (default 56); parent sets `brush_color`/`brush_size`/`brush_hardness`/`brush_effect` (BL-35's finish).
- `get_region_id_at(page_pos)` → 0 = line art, -1 = out of bounds. `get_region_data(id)` returns the JSON region dict for coverage-grid precomputation.
- `get_paint_image()` is a full GPU readback and **blocks** — dev harnesses and the app-quit save only. In the running game use `request_paint_image(callback)` (M6, async). Coverage must sparse-sample at stroke end either way. `get_effect_image()` / `request_effect_image()` (BL-38) are the same pair for the effect mask and return null/false while it is dormant, which is the caller's cue that there is nothing to save.
- Region clipping lives in `scenes/components/brush.gdshader` (`id_epsilon` = half an 8-bit step; ID map sampled with `filter_nearest` hint). The SubViewport is never cleared (`CLEAR_MODE_ONCE`→NEVER); `PaintCanvas` draws only the pending stamp batch each frame.
- `painting_enabled` (BL-10) is the ONE additive gate: false → `begin_stroke()` refuses and emits `paint_blocked(page_position)` instead, and a stroke already down is cancelled. Nothing else in the component reacts to it — pan/zoom and the committed paint are untouched. **Two things drive it now** (BL-36): the padlock and sticker mode, resolved in `ColoringPage._apply_painting_gate()` — the ONE place it is written — and `paint_blocked` is therefore also BL-36's placement hook (`_on_paint_blocked`: locked → wiggle the padlock, else sticker mode → place, so a locked page refuses a sticker exactly as it refuses a stroke).
- `get_sticker_layer()` (BL-36) is the other additive surface: a `StickerLayer` `Node2D` inside `PageRoot`, ABOVE the line art, cleared and re-measured on every `load_page*`. Painting, clipping, recipes and the coverage readback are untouched by it, and it is the parent that places, undoes and persists.
- Smoke test: `<godot_exe> --path godot res://scenes/dev/paint_smoke.tscn` (windowed — headless can't render the SubViewport; append `-- --stay` for manual play, F1 toggles the region overlay). Keep it green after any change to the painting stack.

## The palette — one crayon strip (BL-20…BL-23)

**There is no Child/Adult mode.** BL-20 deleted the split: no mode-select screen, no settings mode switch, no adult palette, no swatch grid, no brush-size slider, and no `GameState.mode`. One flow, one palette, one threshold. `GameState.mode` and the save's `"mode"` key are vestigial — the save READER tolerates the key (`GameState.VESTIGIAL_SAVE_KEYS`) so pre-BL-20 files load at the same `SAVE_VERSION`, and nothing writes or branches on it. Never re-introduce a mode parameter.

- `palette_child.tscn` / `PaletteChild` is **the** palette (the name is historical and deliberately kept — DESIGN.md §3.4 names it): a strip of chunky crayons, 64 px+ touch targets, ONE forgiving 96 px brush, `completion_threshold` 0.90.
- It emits `color_picked(color)`, `brush_size_picked(size)` and `brush_effect_picked(effect)` (BL-35) and **nothing else reaches the paint path**. Everything below (layout, intensity, crayon boxes) is resolved inside the palette; `color_picked` always carries one final `Color`, and a finish never rides inside it — it has its own signal or it does not travel.

### Implemented (M3, reshaped by BL-20…BL-23) — build against these, don't reinvent

- `PaletteDef` (`scripts/resources/palette_def.gd`): `display_name`, `colors` (the DEFAULT crayon box — also what the title screen, the boot splash and the celebration confetti read), `brush_sizes` (**diameters**, feed `PageView.brush_size` directly — shipped `(96)`), `default_brush_size`/`default_brush_hardness`, `completion_threshold` (0.90). Plus the two derived-feature APIs below. It carries **no** mode id and no `shades_per_family`.
- **Intensity ladder (BL-22)** — `PaletteDef.shade_of(base, step)` / `shades_of(base)`. A pure function, never authored: `INTENSITY_STEPS` 7, `INTENSITY_BASE_STEP` 3 (= the crayon's own colour), lightened linearly to `MAX_TINT` 0.72 below it and darkened to `MAX_SHADE` 0.60 above. Because it is computed, every crayon of every set has a ladder and no set can ship without one. Do not add a per-colour shade table.
- **Crayon boxes (BL-23, rebuilt by BL-35)** — `CrayonSetDef` (`scripts/resources/crayon_set_def.gd`): `display_name`, `sort_order`, `colors`, **and one finish** (`effect: StringName`). BL-35's amendment to BL-23's "colours and nothing else" is exactly one field wide, and the rule it amends is unmoved: **a finish is how the paint LOOKS, never how the game PLAYS** — brush size, hardness and the completion threshold stay forbidden on a set and stay on `PaletteDef`, or a box is a difficulty mode again. `colors` **empty means "the palette's own lineup"**, which is what every shipped box does: the boxes differ in their finish, not their colours (BL-35 deleted the five recolours the playtest called "more colour options, not more fun"). Sets are **discovered**, like books: `CrayonSetDef.discover()` scans `res://resources/palettes/sets/*.tres`, sorted by `sort_order`. Shipped ladder, each louder than the last, in **three tiers** (BL-51): box 0 classic wax (the palette's own box) → the BAKEABLE band **Neon Glow** → **Textured Wax** → **Glitter** → the SUBTLE animated pair **Shimmer** → **Twinkle** → the SPECTACLE band **Embers** → **Ocean Glass** → **Aurora** → **Firefly Dust** (`sort_order` 60/62/64/66 above the existing 40/50 — BL-47 had slotted them at 32/34/36/45 *below* shimmer, which a playtest called "missed the point"). `PaletteDef.get_crayon_set_colors(i)` / `get_crayon_set_effect(i)` / `get_crayon_set_name(i)` / `crayon_set_count()` / `wrap_crayon_set(i)` present box 0 and the discovered sets through one index. `wrap_crayon_set` wraps **both** ways (`wrapi`), which is what BL-34's backward cycle rides on.
- **Finishes (BL-35)** — `BrushFinish` (`scripts/components/brush_finish.gd`) is the one table of finish ids → shader mode, `quad_scale`, strength, display name, `animated`. The finish reaches the paint path on its OWN signal, `PaletteChild.brush_effect_picked(effect)` → `ColoringPage` → `PageView.brush_effect`; `color_picked` still carries one resolved `Color` and nothing else, and the paint path never reads palette internals. `set_palette()` primes size → finish → colour; a box change emits the finish once; a crayon or rung pick emits none. `brush.gdshader` bakes it into the stamp (uniforms `effect_mode`/`quad_scale`/`effect_strength`/`effect_seed`), so the flattened SubViewport and the saved PNG carry it for free. The shipped ladder is **classic → glow → grain → glitter → shimmer → twinkle → embers → ocean → aurora → firefly** (re-sorted by BL-51); the first four are bakeable (BL-35) and the last SIX are ANIMATED (BL-38's two, then BL-47's four), which `BrushFinish.is_animated()` is the one branch on. Three rules with teeth: (1) **the region clip owns every finish** — the glow's halo is a wider quad, discarded fragment by fragment outside the locked id like everything else; (2) **an effect must be a function of PAGE POSITION, never of the dab** — dabs overlap ~87%, so a per-dab gradient is overwritten by the next dab and an alpha-modulated grain fills itself in, while a page-space field is idempotent under the overlap and replay-stable; (3) **BL-17 recipes carry `effect` and `effect_seed`**, and `stamp_recipe()` reads them from the recipe rather than the live brush, which is what keeps undo→redo pixel-exact after a box change. `CrayonButton.finish` previews the box in canonical space (never fork the drawing code).
- **Animated finishes (BL-38, widened by BL-47, re-aimed by BL-51)** — the SUBTLE pair **Shimmer** (a sheen that travels across the page) and **Twinkle** (glitter that winks in place), then the SPECTACLE four: **Embers** (live coals — a churning heat bed, a fast flicker, cinders streaming upward, and the one style besides the aurora that MIXES its colour into the wax rather than only adding light, because warm light added to a blue crayon can only ever come out pale mauve), **Ocean glass** (a bright caustic web of ridged threads swimming over the wax), **Aurora** (two rippling ray-striped curtains sweeping the page, carrying crimson-green-violet light AND a ~2.1 rad hue rotation) and **Firefly dust** (a swarm of bright wandering points with wide halos, drawn from the 3x3 cell NEIGHBOURHOOD so a fly's halo is never cut by a cell boundary). They still BAKE a base into the paint layer; what moves lives in the **effect mask** (see above), and five rules have teeth: (1) **the mask is stamped by the brush shader, not composited** — that is why the animation cannot cross a region boundary and why it never marks a texel the wax does not cover; (2) **coverage and completion read the paint viewport and can never see the animation** — an animated stroke's paint layer is byte-identical with the animation running and frozen (`PageView.effect_animation_enabled` is the freeze, and the reduced-motion lever); (3) **every stamp writes the mask, and a bakeable payload is zero**, so ordinary wax over a shimmer erases it through the ordinary blend; (4) **persistence is a second PNG**, `user://paint/<slug>/page_NN_fx.png`, written and restored at exactly the paint layer's save points — the one-readback rule is now "one per LAYER", and a page with no animated wax still costs one and writes one file; (5) **recipes carry `effect_masked`** beside `effect`/`effect_seed`, because the layer wakes lazily and "did this stroke reach the mask" is not derivable later — without it a rebuild stamps pre-activation strokes into the mask and undo→redo stops being byte-stable. `rebuild_paint(baseline, recipes, effect_baseline)` takes both baselines or the animation is lost on the first undo. **BL-47's one architectural change**: the mask's red and green are QUANTIZED STYLE LEVELS (`BrushFinish.MASK_FIELD_LEVELS` / `MASK_SPECK_LEVELS`), not raw amounts, so each channel carries a whole FAMILY of animations — the display shader recovers the stamped level exactly as `mask.rgb / mask.a` (nothing else reads the mask's alpha, and alpha blending makes that ratio the payload at any coverage and any dab depth) and rounds it to the nearest level, while the LIGHT AMOUNT still comes from the raw coverage-weighted channel with a per-style gain. Never move a level that has shipped — every saved `_fx.png` decodes through that table.
- `GameState` autoload (`autoload/game_state.gd`): `get_active_palette()` (one cached `PaletteDef`), `get_palette_scene_path()` (one scene). No mode property, method or signal. Extend it for book/page state and persistence (M5) — no second autoload.
- **Palette contract** — `set_palette(def)` (auto-emits `brush_size_picked`, then `brush_effect_picked`, then `color_picked` once each, so the brush is never colourless, sizeless or finish-less), `color_picked(color)`, `brush_size_picked(size)`, `brush_effect_picked(effect)`, `sticker_picked(sticker)` + `sticker_mode_changed(active)` (BL-36), `select_color(i)`, `select_brush_size(i)`, `get_selected_*()`, `get_color_buttons()`, `get_brush_size_controls()` (always empty — one brush), `get_pick_preview()` (BL-15). Wiring a coloring screen = instantiate `GameState.get_palette_scene_path()`, connect those signals to `PageView.brush_color`/`brush_size`/`brush_effect`, set `brush_hardness` from the def, call `set_palette`, then `set_layout()` for the orientation.
- **Sticker sets (BL-36)** — the cycle ring **keeps going past the last crayon box** into the discovered `StickerSetDef`s and wraps home from the last one: `stage_count()` = `crayon_set_count()` + `sticker_set_count()`, `get_stage_index()`, `set_stage(i)`, `is_sticker_stage(i)`; `next_crayon_set()`/`prev_crayon_set()` keep their BL-34 names and walk the whole **ring**. In sticker mode the strip is `StickerButton` cards instead of crayons (`get_sticker_buttons()`; `get_color_buttons()` is EMPTY, `get_strip_buttons()` is whatever is up), the intensity tile is hidden and the pick bubble is not raised. `sticker_mode_changed` goes out BEFORE the pick that goes with it, and **entering** sticker mode emits neither `color_picked` nor `brush_effect_picked` — no colour and no wax changed and there is nothing to paint with; **leaving** emits the mode signal first, then the box's finish, then its colour. Sets are **content, not palette data**: `StickerSetDef.discover()` scans `res://resources/stickers/*/sticker_set.tres` (dev fixtures, excluded from every release export like `resources/books/*`) then `user://dlc/<pack>/stickers/<set>/sticker_set.json`, de-duped by `set_uid` with the built-in winning — the `BookDef` rule, one level smaller. The strip discovers them ONCE, in `set_palette()`.
- **The pick is always "crayon C of box B at rung R"**, resolved in `PaletteChild.get_selected_color()` and nowhere else. `select_color(i)` picks the crayon and **resets the rung** to the crayon's own colour; `select_intensity(step)` picks the rung; `set_crayon_set(i)` / `next_crayon_set()` / `prev_crayon_set()` swaps the box (and resets to its first crayon, own colour, colours face). Swapping the VIEW (`set_view()`, `VIEW_COLORS` / `VIEW_SHADES`) emits nothing — it is not a pick.
- **Three tools on the strip** (BL-34 reshaped BL-23's two), all primitive-drawn, all OUTSIDE the crayon `ScrollContainer` so a slide can never land on one:
  - a `CrayonCycleButton` **bar at each OUTER END of the strip's long axis** — back at the start, forward at the end. 68 px thick along the strip, stretching across it. Each previews the box IT would fetch (a colour stripe on its outer edge) and carries the pip row (one per box, current filled). The leading bar shares the tool band with the intensity tile; the trailing one caps the far end alone — an end-band each would cost 20 px more of the strip's length than BL-33's fit can spare.
  - `IntensityButton` (BL-22, 88 px, swaps colours ↔ ladder, draws the ladder with the ACTIVE rung ringed), unchanged, in the leading band.
  - The box's NAME is a transient `CrayonBoxFlash` banner over the strip on every cycle ("Neon!"), not a label: pop/hold/fade, `MOUSE_FILTER_IGNORE`, blocks nothing, hides itself on focus loss. The old `CrayonBoxButton` carton tile is deleted and the smoke asserts it stays deleted. **BL-23's "two 88 px tiles share the short axis; a third overflows silently" gotcha is obsolete** — that geometry is what BL-34 reworked.
- Smoke test: `<godot_exe> --path godot res://scenes/dev/palette_smoke.tscn` (windowed; `-- --stay` to inspect, `-- --shot <path>` saves a screenshot). Keep green alongside paint_smoke.

### Layout: bottom row or side dock (BL-21)

- Portrait keeps the crayons in a strip along the **bottom** of the canvas; landscape docks them as a vertical **column** on the side. Same scene, same instance — `PaletteChild.set_layout(LAYOUT_ROW | LAYOUT_COLUMN)` flips the body box's direction, the crayons' orientation, the crayon fit and the pick bubble's placement. The row is `STRIP_THICKNESS` (212 px) tall; the column is `COLUMN_THICKNESS` (260 px) wide — BL-33 gave it its own number, because two ranks of a 212 px strip are 89 px crayons that read as nubs, and width is what a landscape screen has spare.
- **The parent decides, from its ASPECT RATIO** — `ColoringPage.is_landscape()` is `size.x > size.y`, never a pixel width (DESIGN.md §3.5: a portrait window's logical canvas never gets narrow). `coloring_page.tscn`'s `Ui/Body` is a plain `BoxContainer` because `HBoxContainer`/`VBoxContainer` refuse `set_vertical()`.
- `CrayonButton` draws in a **canonical** space (tip up, lift rising) and `ORIENT_LEFT` rotates it a quarter turn anticlockwise before anything is drawn. Consequences that come for free and must stay that way: the lift points **into the canvas** in both orientations, `LIFT_HEADROOM` still reserves the bounce overshoot at the canonical top, and the halo still flattens along the axis the scroller clips. Use `box_for(orientation, canonical)` / `lift_direction()`; never fork the drawing code.
- **The crayon is resizable (BL-33)**: the palette hands it a `canonical_size`, and `LIFT_PX` / `LIFT_HEADROOM` / the paddings are all multiplied by `length_scale()`. Ask it, never the constants — `resting_lift()`, `lift_headroom()`, `current_lift()`. The invariant is a ratio now: `lift_headroom() >= resting_lift() * SELECT_BOUNCE_SCALE` at **every** size, so the bounce peak is never clipped.
- `PickPreview` parks **above** the finger for the bottom row and **left** of it for the right-hand column (`PLACE_ABOVE` / `PLACE_LEFT`); the whole geometry is one direction vector (`get_tail_direction()`), so a third placement is one constant. Slide-to-select needs nothing: `PaletteSlideInput` hit-tests real control rects in viewport space.
- ~~Known trade: ten crayons do not fit a docked column on a short landscape canvas, so the strip scrolls~~ — **reversed by BL-33. The strip does not scroll.** `PaletteChild._fit_crayons()` budgets the strip's long axis from constants (never measured rects — a measured fit oscillates), divides by the crayon count, clamps at `CrayonButton.MIN_TOUCH_TARGET` (64 px, non-negotiable) and at `CANONICAL_ASPECT`, and **wraps to another RANK across the strip** (up to `MAX_RANKS` 3, fewest that fit wins) rather than scroll. Shipped: 1 rank in the portrait row, 2 ranks of 5 in the docked column. `ScrollContainer` modes are `DISABLED` unless even three ranks of floor-sized crayons overflow (`fits_without_scrolling()`), which the shipped lineup never does; the scroller survives only as the crayons' host and slide-to-select's hit area. One rank of a set that is genuinely too long is still the fallback the scroll exists for.

### Implemented (M5) — app shell & persistence

- `main.tscn` / `scripts/main.gd` (`class_name Main`) is `run/main_scene` and the **only** node that knows the flow: Title → BookSelect → ColoringPage → (Back) → BookSelect. There is no mode select (BL-20) and no completion screen (BL-11). It frees/instantiates screens behind a 0.25 s fade, and owns the **overlays** (settings gear, settings panel, and WP10's adult gate / account panel / pack shop) — that is how `book_select.tscn` gained a settings entry point without knowing about one. (**BL-48/BL-49**: those two corner buttons are phone-sized now, so `main` also *measures* them and tells the shelf what strip they occupy — `BookSelect.set_chrome_band()`. ### Implemented (M6) — the mobile pass

- **Renderer is now Mobile** (Vulkan), not Forward+. Chosen because Compatibility/OpenGL exposes **no `RenderingDevice`**, which would kill the async readback below; between the two Vulkan renderers, Mobile is the cheaper pipeline for a 2D game. DESIGN.md §3.5 has the evidence. Anything that touches `RenderingDevice` must still degrade gracefully when it is absent.
- **The paint readback is asynchronous.** `AsyncReadback` (`scripts/components/async_readback.gd`, static helpers over an injected `Viewport`) wraps `RenderingServer.texture_get_rd_texture()` → `RenderingDevice.texture_get_data_async()`. `PageView.request_paint_image(callback)` is the non-blocking twin of `get_paint_image()`; it returns **false without calling back** when the async path is unavailable, which is the caller's cue to fall back to the blocking call. Measured on the M6 dev box under default FIFO v-sync: **529.8 ms blocked synchronously → 0.10 ms** to queue the async one, image delivered on the **main thread** ~2 frames later.
  - `get_paint_image()` is still there and is still correct — dev harnesses and the app-quit save use it deliberately.
  - Two rules come with async: a readback can be a couple of frames stale (fine, coverage is monotonic and the completion flip already tolerated it), and **the engine must never be torn down while a readback is queued** — that is a reproducible hard crash (signal 11 during shutdown, any renderer). `AsyncReadback.drain(tree)` before any `SceneTree.quit()`; `main.gd` does it on close, every dev harness does it in `_finish()`.
- **`main.gd` owns the quit**: `SceneTree.auto_accept_quit` is off, and `NOTIFICATION_WM_CLOSE_REQUEST` runs save → drain → quit. `Main.quit_on_close_request = false` is the harness hook (it hands `auto_accept_quit` back so a `--stay` window still closes).
- **`ColoringPage` coverage** is a *loop* now (`_run_coverage_cycles`): a stroke ending during the two-frame flight lands in `_pending_regions` after the batch was taken, so the cycle repeats until that set is empty. Coalescing and skip-when-done are unchanged — five strokes in one burst still cost one readback.
- **Save points** unchanged in *when*, changed in *how*: page complete / leaving the book / navigating use `persist_current_page_settled()` (async); app quit uses `persist_current_page()` (blocking — there is no next frame to deliver to, and losing a page is worse than a stall on a frame nobody sees). Leaving the book **awaits** the save before emitting `back_requested`, or the parent would free the screen out from under the callback.
- **Page navigation**: `ColoringPage.can_go_to_page()` / `go_to_page()`, driven by prev/next buttons in the toolbar. A jump **saves first, then swaps instantly** — no flip (BL-4 carved out one exception: the forward step off a page the player just finished, which is now where the flip lives). `is_transitioning()` now covers navigation too. ~~Rule: any page already reached … plus exactly one page forward when the current page is complete~~ — **BL-10 deleted that gating and `furthest_reached_index()` with it**; every page is always reachable.
- **Portrait**: ~~`ModeSelect` stacks its cards below aspect 1.0~~ (that screen is gone, BL-20 — but its lesson is now BL-21's: a container that has to flip must be a plain `BoxContainer`, because Godot refuses `set_vertical()` on `HBoxContainer`/`VBoxContainer`); `TitleScreen` sizes its paper and lettering to the screen instead of demanding 820 px; `ColoringPage` drops the toolbar's page title below 620 px; `SafeArea` (`scripts/components/safe_area.gd`) wraps `ScreenHost` + `Overlays` in `main.tscn` for notch margins (zero on a windowed desktop by design — `get_display_safe_area()` reports the *work area* there, not a cutout). Gotcha: `canvas_items`/`expand` stretch means the logical canvas never gets narrower than 1152 — portrait layouts must key off **aspect**, and width-driven ones have to be tested by resizing the screen `Control`, not the window.
- **First real art book**: `resources/books/coyote/` + `assets/books/coyote/`. **ONE page** (corrected by BL-9 — it was briefly imported as two): the visible art is the detail drawing, its 2 regions (coyote + paper) come from the outline mask.
